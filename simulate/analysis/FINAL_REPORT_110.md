### 2.3 BY_LAW — потребують підзаконного акта (37 елементів)

Норма міститься не в законі, а в підзаконному акті (Порядок, Інструкція, Правила, Положення), якого **немає в `laws/`**. **Відкладено (Крок 1)** — користувач надасть точні номери/файли.

Включає: #40 (встановлення особи віком до 16 років — Порядок вчинення нотаріальних дій), #89–#110 (Закон про консульську службу, Інструкції, Правила АЦС тощо).

### 2.4 NOT_IN_LAW — загальні знання (17 елементів)

Питання про загальні знання (ЄС, інституції, міжнародні конвенції), яких немає в конкретному законі. Ref не застосовний — це нормально для тестових питань на загальну ерудицію.

## 3. LLM-семантичний аудит (Крок 2 + Re-audit)

### 3.1 Покращення extraction ([`robust_extract.py`](robust_extract.py))

- Обробка «§ N» (Регламент КМУ).
- Обробка дефісних пунктів «N-M» (напр. п. 8-1) та усунення хибних збігів із діапазонами «X-N».
- Розрізнення постанову-vs-Правила (маркер «Ці Правила визначають»).
- Ключове-зважена дезінтеграція неоднозначних пунктів у консолідованих документах (напр. п.19 документування).
- Обробка «ст. N» через делегування `simulate.extract_article_by_ref`.

### 3.2 Виправлення truncation

- `verify_with_llm` отримав параметр `max_chars` (за замовчуванням 3000). Аудит передає `max_chars=12000`.
- Це усунуло хибний False для #2 (ст.1 громадянство: «двох років» на позиції 8845, поза межами 3000).

### 3.3 Обробка питань «що НЕ...»

- Додано `verify_which_not` для питань типу «що не відноситься / не є / не можуть» — правильна відповідь навмисно ВІДСУТНЯ в статті, тому логіка перевірки інвертована.
- Усунуло хибні False для #11, #12, #35.
