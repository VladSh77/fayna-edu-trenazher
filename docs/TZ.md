# ТЗ — `fayna-edu-trenazher`: універсальний рушій тестів для освітніх проектів

> Версія 1.0 · 15.08.2026 · Замовник: власник · Перший споживач: Ірина, тести МЗС 16.09.2026

## 1. Objective

**Що:** одне репо, куди кидають *тему + матеріал + питання*, а на виході — онлайн-тренажер,
що відкривається за посиланням з телефона й готує людину до іспиту.

**Навіщо:** зараз кожен курс робиться з нуля (Odoo-модуль виховника — 12 700 рядків,
потребує сервера, ніде не встановлений). Треба рушій, який не залежить від сервера
і перевикористовується під будь-яке навчання.

**Перший банк:** законодавство + країнознавство для добору на віцеконсула в Познані
(1819 питань уже зібрано, `trenazher/bank_final.json`).

**Не робимо:** бекенд, реєстрацію, акаунти, збереження персональних даних на сервері,
видачу сертифікатів. Це рушій підготовки, не система атестації.

## 2. Архітектура

Статичний сайт, нуль бекенду. Хостинг — **GitHub Pages, публічно** (рішення власника 15.08).

```
fayna-edu-trenazher/
  index.html              # рушій цілком: HTML+CSS+JS в одному файлі, без CDN
  banks/
    _schema.json          # схема банку (контракт)
    mzs-2026.json         # банк Ірини
    manifest.json         # перелік доступних банків для стартового екрана
  tools/
    TZ_generate_bank.md   # шаблон ТЗ, за яким АІ робить новий банк з матеріалу
    validate_bank.py      # перевірка банку проти схеми
  docs/TZ.md · README.md · CLAUDE.md
```

**Чому один HTML-файл:** відкривається з файлу, з пошти, з Pages, працює офлайн у літаку
й у метро, не ламається від зміни CDN. Обмеження: без збірки, без фреймворків.

## 3. Контракт банку питань (`banks/_schema.json`)

Формат уже існує у `bank_final.json` і **не змінюється** — рушій підлаштовується під нього:

```json
{
  "title": "Тести МЗС — віцеконсул 2026",
  "total": 1819,
  "sections": [
    {"id": "gromadianstvo", "title": "Закон про громадянство України", "questions": [...]}
  ]
}
```

Питання:
```json
{"id": "dodatok-4-001",
 "source": "dodatok-4",
 "question": "текст питання",
 "correct": "правильна відповідь",
 "wrong": ["невірна 1", "невірна 2"]}
```

**Інваріанти, які перевіряє `validate_bank.py`:**
- рівно одна `correct`, від 1 до 3 елементів у `wrong`;
- `correct` не збігається з жодним `wrong` (нормалізація: трим, регістр, подвійні пробіли);
- `id` унікальні в межах банку;
- `question` не порожнє й не коротше 10 символів;
- жодне питання не належить двом секціям.

Порушення — ненульовий exit і перелік поганих `id`.

## 4. Поведінка рушія — те, що бачить користувач

### 4.1 Стартовий екран
Список банків із `manifest.json`. Для банку — назва, кількість питань, кількість розділів,
і **збережений результат** (скільки пройдено, % правильних) з `localStorage`.

### 4.2 Вибір розділу
Список розділів законодавства. Біля кожного: `пройдено N/M · правильно XX%`.
Кольорова смужка прогресу: <75% червона, ≥75% зелена. Кнопка «усі розділи підряд».

### 4.3 Режим НАВЧАННЯ (головний)
- Питання по одному на екран, варіанти перемішані випадково при кожному показі.
- Користувач тисне варіант → **миттєвий фідбек без переходу далі**:
  - обраний правильний → підсвічується **зеленим**;
  - обраний невірний → підсвічується **червоним**, і **одночасно зеленим — правильний**,
    щоб людина побачила, як мало бути. Це головна навчальна дія, не прибирати.
- Далі — кнопка «Наступне». Назад повертатись можна, відповідь лишається видимою.
- Проходяться **всі** питання розділу, порядок — послідовний (не випадковий),
  щоб можна було вчити систематично й повертатись на те саме місце.
- Зверху лічильник: `питання 12 / 106 · правильно 9 (75%)`.

### 4.4 Режим ЕКЗАМЕН
- 30 випадкових питань з обраних розділів, ліміт 30 хв, поріг **75%**.
- Правильні відповіді під час проходження **не показуються** — лише в кінці, розбором.
- Підсумок: %, зараховано/не зараховано, перелік помилок із правильними відповідями.

### 4.5 Прогрес
`localStorage`, ключ на банк. Зберігається: останнє питання кожного розділу, лічильники
правильних/невірних, історія екзаменів (дата, %, результат). Кнопка «скинути прогрес»
з підтвердженням. Нічого не йде на сервер.

## 5. Мобільний UX — обов'язкові вимоги

- Верстка від 320 px; варіанти відповідей — кнопки на всю ширину, висота ≥48 px
  (палець, не курсор).
- `<meta name="viewport" content="width=device-width, initial-scale=1">`;
  `-webkit-text-size-adjust: 100%`.
- Безпечні зони iPhone: `padding: env(safe-area-inset-*)` — кнопка «Наступне» не має
  ховатись під домашню смугу.
- Шрифт питання ≥17 px, міжрядковий ≥1.5 — тексти законів довгі.
- Темна тема через `prefers-color-scheme`; зелений/червоний читабельні в обох
  (контраст ≥4.5:1) і **дублюються значком** ✓/✗ — 8% чоловіків не розрізняють ці кольори.
- Нуль горизонтального скролу.

## 6. Генерація нового банку — конвеєр «кинув матеріал → отримав тест»

`tools/TZ_generate_bank.md` — шаблон ТЗ для зовнішньої моделі. На вході: тема, вихідний
текст (закон, конспект, PDF), бажана кількість питань, мова. На виході: JSON за §3.

Правила в шаблоні:
- питання лише з поданого матеріалу, вигадувати норми заборонено;
- невірні варіанти правдоподібні (з сусідніх норм), не абсурдні;
- заборонено «всі відповіді правильні» / «жодна»;
- кожне питання — з полем `source` на розділ вихідника, щоб можна було звірити.

Прогін — `docs-sorter/research_cli.py chat`, далі обов'язково `validate_bank.py`.

## 7. Boundaries

**Always:** один HTML без зовнішніх залежностей · банк валідується перед комітом ·
зелений/червоний завжди з дублем значком.

**Ask first:** зміна порога 75% · зміна формату банку · додавання бекенду чи акаунтів.

**Never:** персональні дані учасників на сервері · CDN-залежності · відправка прогресу
кудись назовні · публікація банку, який не пройшов `validate_bank.py`.

## 8. Success Criteria

- [ ] Ірина відкриває посилання на iPhone і проходить розділ, не встановлюючи нічого.
- [ ] Невірна відповідь підсвічується червоним, правильна — зеленим, одночасно.
- [ ] % правильних рахується по кожному розділу окремо й переживає перезакриття браузера.
- [ ] Екзамен: 30 питань, 30 хв, поріг 75%, розбір помилок у кінці.
- [ ] `validate_bank.py` на банку МЗС — exit 0.
- [ ] Новий курс додається одним JSON у `banks/` без правки рушія.

## 9. Відкриті питання

- Банк МЗС містить **224 записи-сміття** з «Типової інструкції з діловодства»
  (не питання, а суцільний текст із переліками) — вичистити до публікації.
- Етап **E0.2** — ручна звірка 10 випадкових питань із нормою закону — не пройдений.
  Без неї тренажер може вчити неправильного. Блокує оголошення банку готовим.
- Країнознавство (конспект 115 КБ) банку ще не має — окремий прогін після законодавства.
